Primeira versão do **hbt**: túnel reverso (TCP, UDP e HTTP) em Rust, no estilo do ngrok. Exponha um serviço que está atrás de NAT/firewall por uma porta pública do seu VPS.

## Instalação

**Cliente** (Linux e macOS):
```sh
curl -fsSL https://github.com/npbandeira/hbt/releases/download/v0.1.0/install.sh | sh -s -- --version v0.1.0
hbt configure --server SEU.VPS --token ID.SEGREDO
hbt http 3000
```
No Windows, baixe `hbt-windows-x86_64.exe` abaixo.

**Servidor** (Linux com systemd):
```sh
curl -fsSL https://github.com/npbandeira/hbt/releases/download/v0.1.0/install.sh | sh -s -- --server --version v0.1.0 --domain tunnel.exemplo.com
sudo -u hbt hbt-server token create meu-notebook
```
Libere no firewall `7000/tcp`, `80/tcp` e `20000-30000` (tcp e udp).

## O que tem

- Túneis **HTTP** por subdomínio (`hbt http 3000`), **TCP** (`hbt tcp 22`) e **UDP** (`hbt udp 51820`), com porta ou subdomínio escolhido ou sorteado.
- **Uma conexão só por túnel**: todo o tráfego passa multiplexado (yamux) dentro dela. Uma conexão pública nova custa só 1 RTT até o cliente.
- **Tokens por cliente** com limite de portas e subdomínios, e revogação na hora (`hbt-server token create|list|revoke`).
- **Métricas Prometheus** (`/metrics` em `127.0.0.1:9477`) e um stack Prometheus + Grafana com dashboard pronto para rodar na sua máquina (`scripts/observability.sh`).
- Reconexão automática com backoff exponencial; serviço systemd endurecido.

## Desempenho medido

Servidor numa VM com 1 vCPU, ping de 63 ms até o cliente:
- requisição com conexão nova: **69 ms** (praticamente só o ping);
- 50 usuários simultâneos abrindo conexões novas: ~218 req/s, com o servidor abaixo de 5% de CPU.

Em localhost, com o servidor limitado a 1 CPU: ~50 mil req/s com keep-alive.

## Limitações conhecidas

- **Sem TLS entre cliente e servidor.** A autenticação é por desafio HMAC (o segredo não trafega), mas o tráfego vai em claro. Para HTTPS público, ponha Caddy/nginx na frente; serviços que já usam TLS/SSH ficam protegidos.
- **UDP passa dentro de TCP**: sob perda de pacotes a latência sobe. Bom para DNS e WireGuard; ruim para jogos e voz em rede ruim.
- Até 1024 conexões simultâneas por túnel; acima disso as novas esperam vaga.
- Um processo `hbt` por túnel.
